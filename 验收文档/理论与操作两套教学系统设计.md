# 理论学习与操作学习的独立出题、批改设计

本次反馈要求两套系统分开。已有 S4 计划包含操作学习答题与严格序列比对，但没有理论题出题管理。本文件补齐理论出题和教师操作批改工作台设计；只在本轮落实导航、共享权限和界面返修，不把尚未开发的能力做成可点击的假入口。

## 入口与工作流程

教师侧栏保持首页、题目管理、考试管理三个主项。题目管理可展开为理论学习、操作学习，分别进入各自系统。

| 环节 | 理论学习 | 操作学习 |
| --- | --- | --- |
| 当前入口 | `/teacher/questions`：班级下拉、学号搜索、学生名单、作答批改 | `/operations/manage`：操作题库、题目设置、站场录制、检查发布 |
| 出题入口设计 | `/teacher/theory/questions`：理论题库；`new`、`:id/edit`、`:id/review` 独立编辑与发布 | 已有操作题页面，继续使用独立标准站录制流程 |
| 编辑内容 | 理论专题、题干、客观题选项/答案、论述评分要点、各项分值、发布班级 | 题干、班级、初始站场条件、通过实操采集的标准日志 |
| 学生提交 | 结构化选项、文本和论述内容 | 绑定题目版本的操作事件序列，不接收理论答案表单 |
| 客观核对 | 使用理论题自身的答案、允许值和分值规则 | 依原 S4 规则：严格完整匹配为 100 分；漏点、多点、错序、参数不同为错误且分数为空 |
| 教师批改 | 学生名单 → 作答列表 → 单份批改；客观项、论述评分和评语分开 | `/operations/reviews` → 班级/学号/题目筛选 → 单次操作详情；展示标准与实际日志、首个差异、比对结果和讲解；教师留评语、确认已查看，不擅自改写确定性比对规则 |
| 当前实现状态 | 原六专题的理论作答、批改已实现；新增理论题出题管理按下述 T1 单独开发 | 出题、录制、发布已实现；学生答题与结果工作台按 S4 开发 |

进入各分支后，页面标题和工具栏各自固定；刷新按钮置于相应名单或题库工具栏中。理论出题与批改后续在理论分支内用“题库管理 / 作答批改”切换，操作分支内用“操作题库 / 操作批改”切换。两分支不通过同一个万能编辑器判断题型，也不在切换时保留不相关的刷新按钮。

## T1：补充理论出题管理

新增理论题使用独立的 `theory_authored_questions`、`theory_question_versions`、`theory_assignments` 保存题目、不可变版本和班级发布关系；新增题目的答卷与评阅使用 `theory_authored_attempts`、`theory_authored_reviews`。这些表不引用操作会话，不保存标准操作日志。沿用理论评分辅助函数时，仍以理论版本的字段与评分要点为输入。

现有六专题、原 18 道题和原 `lab_attempts` 历史保留。原题不直接进入自由编辑器，也不通过修改启动种子来出新题；新增题单独存储并显示在所属专题的“教师发布题目”区域，避免重启时被教材种子覆盖。两个理论来源在批改入口汇总，但详情接口明确来源，不能把相同数字 ID 当成同一份答卷。

理论编辑表单支持选择题、填空/顺序填写、论述项，逐项填写答案或评分要点。保存草稿允许不完整，发布要求题干、班级、每项分值及对应答案/评分要点完整，分值合计明确。学生提交时保存题目、答案与评分要点快照；教师后续修改产生新版本，不改变旧答卷。

教师通过共享理论题库协作出题和评阅。保存题目使用版本修订号，评阅使用现有评阅修订标识；其他教师已修改时返回冲突并要求重新读取，不能静默覆盖。创建人和评阅人用于审计，不用于把本课程题目、班级或答卷隔离成私人数据。

## S4：操作学习与操作批改

继续使用独立的操作题、操作版本、操作会话与事件模型。学生作答会话必须与教师标准录制、预览分开，并绑定作答开始时的已发布版本；标准答案在提交前不向学生开放。

操作工作台显示实际点击、业务拒绝、标准步骤、差异与确定性结果，保留原日志次序；AI 仅解释结果，不决定比对分数。教师查看、评语和确认状态记录在操作评阅表，不能写入理论评阅记录。操作题的班级可见性仍在服务端检查，教师共享不能扩大为学生互看答卷。

## 班级、权限与删除

两套系统的班级字典都来自现有学生资料的 `class_name`，不让教师靠手输创建另一套班级名称。当前操作出题通过 `/api/operations/classes` 获取去重班级及人数；理论名单从相同学生资料提取下拉选项，后续可提取为共享教学字典接口。没有班级时提示在用户管理完善学生资料；已有版本中的往届班级仍显示，不被自动清空。

所有教师与管理员共享本课程题目、版本、标准答案、作答和评阅数据。其他教师的录制可以只读查看、下载；正在执行的站场仍由发起人操作，防止两人向同一状态机同时发指令。这是运行会话的操作边界，不是题库或日志的数据隔离。

当前 S3 尚无学生操作答卷，因此“删除操作题”永久删除该题及全部版本、标准答案和录制/预览日志，必须先确认，且所有会话结束后才能删除。进入 S4 后，若版本已被学生答卷或考试引用，删除接口必须改为拒绝物理删除并引导停用，保留历史成绩依据。理论原教材题保留；新理论题也按“未引用可删、已引用只停用”的规则设计。

## 开发顺序与验收

本轮先完成 S3 返修，由用户查看。T1 理论出题是正式计划中新补充的独立工作项；S4 操作学习、操作批改沿用原阶段，均不在本轮擅自实现。

T1 验收需要覆盖：教师甲出题、教师乙修改与批改；真实班级下拉；理论发布与学生可见性；旧答卷快照不随改题变化；重启不覆盖新增题；六专题与旧历史保留；理论接口拒收操作事件载荷。

S4 验收需要覆盖：标准与实际严格比对；真实重复点击、拒绝和错序；提交前不泄漏答案；教师共享查看操作结果；其他学生无权查看；AI 异常不改变结果；操作接口拒收理论评分表单；已被答卷引用的题目不能物理删除。
