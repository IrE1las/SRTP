# 联锁表解释规则（通用）

> 用途：**考核学生办理进路**。给定〔车站数据 + 正确联锁表 + 学生办理的进路〕，本规则用于**逐列解释每个元素为何如此**，并**诊断学生的漏选 / 多选 / 错选**。
>
> 本规则是**通用**的：所有车站相关的具体名字（道岔、信号、股道、区段、方面）一律从 `station_topology.json` 读取，规则正文只给**判定原理**与**解释/诊断模板**，不写死任何单个车站的设备名。正文中形如"（示例：…）"的内容仅为说明，不是规则的一部分。

---

## ★ 面向学生的解释输出规范（必读，最高优先级）

学生**看不到本规则文件**，也可能**没学过计算机联锁、不懂英文**。给学生的每一句解释都必须遵守：

1. **绝不出现规则条号或内部标签**：不要写 `§5.1`、`§6.1`、`A 类`、`优先级3` 之类——这些只是系统内部编号，学生看了莫名其妙。
2. **绝不出现英文单词或数据字段名**：如 `connectivity_graph`、`terminal_button_type`、`has_train_departure_signal`、`receive_tracks`、`button_suffix`、`direction` 等，一律换成中文说法（"渡线连通关系""该股道终端按钮类型""是否有出站信号"…）。
3. **保留现场实际设备名，但用中文补全**：道岔编号（如 5/7、9/11）、信号机名（如 D3、XD、S5）、轨道区段名（如 25DG、7DG）、按钮——这些印在联锁表和现场设备上，学生认识；说的时候补一个中文量词/身份，如"5/7 号道岔""D3 调车信号""XD 进站信号""25DG 道岔区段""列车按钮 / 调车按钮"。
4. **用值班员熟悉的现场语言**：锁闭、扳动、挤岔、侧撞、迎面、追尾、占用、封锁、防护、切出股道、直向通过、侧向通过、走行。
5. **每条解释三要素，说人话**：①错在哪（漏了 / 多了 / 选反了）②为什么（结合这条进路实际怎么走、占哪些股道区段）③不纠正会怎样（挤岔 / 侧撞 / 迎面冲突 / 进路走不通）。
6. **不写来源出处**：不要在给学生的文字里注明"依据某某文件第几行 / 某某表 / 某某 json"——这些是系统内部依据，学生只需看到解释本身。

> **反面（禁止）**：「按 §5.1 判据，D3 不在走行区段，connectivity_graph 显示其被 lock…」
> **正面（应当）**：「D3 调车信号不该封锁。这条进路从东郊经 III 道拐到 5 道，全程不走 I 道，而 D3 在 I 道上，跟本进路没有冲突；多锁它只会白白挡住 I 道那边的调车作业。」

> 说明：下文各章节标题里的 `§编号`、以及"判定原理"里出现的数据字段英文名，都是**给系统/教师看的内部结构**，**严禁**照搬进给学生的解释文字。

## 0. 零基础概念

- **联锁表**：以进路为单位，规定每条进路所需的道岔位置、应检查的轨道区段、敌对信号等。
- **进路**：列车/调车从始端信号到终端信号经过的路径。
- **道岔**：切换轨道的设备。**定位**=直向通过；**反位**=侧向通过（换股道）。
- **双动渡线**：两个道岔联动（如 `A/B`）。**交叉渡线**：两对渡线在同一处交叉（一对使用时另一对须防护）。
- **无绝缘节 / 侵限**：某些道岔侧向无绝缘节，使相邻区段的分界受道岔位置影响，邻接区段需**条件检查**。
- **敌对进路**：两条进路不能同时建立。来源：区段共用、道岔冲突、迎面冲突。
- **接车**=列车从站外进入车站；**发车**=列车从车站驶向站外。
- **办理进路**：值班员/学生按下始端与终端按钮，系统锁闭道岔、检查区段、封锁敌对信号。学生可能**漏锁**、**多锁**或**选错道岔位置/区段/敌对信号**——本规则据正确表解释每处对错。
- **列车信号与调车信号的区别**：
  - 列车信号机（如 S5、S4、SIII、SII）：防护**列车进路**，显示红/绿/黄等列车信号。列车按钮后缀为 **LA**（如 S5LA）。
  - 调车信号机（如 S5D、S4D、SIIID、SIID）：其中"D"为"调车"拼音首字母，防护**调车作业**（机车转线、编组等），通常显示月白灯（允许调车）和蓝灯（禁止调车）。调车按钮后缀为 **DA**。
  - 出站兼调车：S5D 通常装设在 S5 机柱上（或旁边），构成矮柱调车信号机构，形成"**出站兼调车**"信号机。S5 和 S5D 是**同一机柱上的两套不同机构**，分别服务于列车进路和调车进路。S4/S4D、SIII/SIIID、SII/SIID 同理。

## 1. 输入与数据来源

| 输入 | 作用 |
|------|------|
| `station_topology.json` | **唯一语义来源**。道岔连通、信号类型/朝向/按钮后缀、股道终端信号、区段范围、方面接发车股道、无绝缘节侵限、交叉渡线配对等，全部显式读取，**禁止从名字推测**。 |

## 2. 联锁表 14 列

```
方面, 进路内容, 进路方式, 排列进路按下按钮, 确定运行方向道岔,
信号机名称和显示, 表示器, 道岔, 敌对信号, 轨道区段,
迎面进路(列车), 迎面进路(调车), 其他联锁, 进路号码
```

括号约定：`()`=反位，`[]`=防护定位，`[()]`=防护反位，`{}`=带动，`<S位置>R`=条件区段，无括号的 `A/B`=定位（或不在路径的邻接定位）。

**考核范围**：本系统重点考核 **道岔、敌对信号、轨道区段、按钮** 四列的对错解释；**进路方式列的"变通按钮"暂不参与考核**（其取值 BA / 单置信号反方向按钮的选择，现有数据不足以唯一判定，见 §9 附注）。

## 3. 通用解释方法：先复原"这条进路的走行事实"

解释任何一列之前，先据数据把这条进路的**客观事实**复原一次（这是所有解释的共同依据）：

```
始端 = 进路起点信号（其股道、朝向从 JSON 读）
终端 = 接车：目的股道（"至X股道"）；发车：本方面出站咽喉股道（external_directions[].departure_throat_track）
行进方向 = 接车 → X 增大；发车 → X 减小

沿行进方向从始端追踪到终端，记录：
  ① 实际走行的股道序列与每次换股道的渡线点（切入点/切出点的 X）
  ② 每个道岔组：是否在走行线上、直向还是侧向、是否交叉渡线需防护、是否提前切出（带动）
  ③ 实际占用的区段范围（换股道后：原股道切出点之后、新股道切入点之前，都不算占用）
```

> **走行事实是解释的地基**。学生大部分错误，本质是对"这条进路到底走哪、占哪"理解错了。解释时先陈述事实，再据事实指出对错。

## 4. 道岔列：原理 + 解释 + 诊断

### 4.1 判定原理（通用）

对车站**每一个**道岔组，判定其在本进路中的角色：

| 写法 | 角色 | 判定条件（通用） |
|------|------|------------------|
| `A/B` | 路径上·定位 | 走行路径经过该道岔且**直向**通过 |
| `(A/B)` | 路径上·反位 | 走行路径经过该道岔且**侧向**通过（在此换股道） |
| `[A/B]` | 交叉渡线·防护定位 | 与之交叉的另一组渡线在本进路反位使用 → 本组锁定位防护交叉点 |
| `{A/B}` / `{(A/B)}` | 带动 | 道岔与路径上的某道岔**同处一个道岔区段**，进路不经过它，但区段锁闭时会把该区段内所有道岔一起锁住；若它的当前位置会阻塞平行进路，则必须预先带动到不阻塞平行作业的位置 |
| `A/B`(不在路径) | 邻接定位 | 道岔不在走行线，但其所在区段与路径区段同股道紧邻，且定位时的直向连通影响路径区段电路连续性 |
| 不写 | 无关 | 以上均不满足 |

### 4.2 解释模板（"为什么是这个值"）

- **定位**："{道岔} 定位——本进路从 {始端} 沿 {股道} 直向通过该道岔，不在此换股道，故须锁闭在定位以保证直向且防止被扳动。"
- **反位**："{道岔} 反位——本进路要从 {股道A} 切换到 {股道B}，经该渡线侧向通过，故锁反位。"
- **防护定位 `[]`**："{道岔} 定位防护——它与 {交叉的另一组渡线} 组成交叉渡线；当那组在本进路反位占用交叉点时，本组必须锁定位，防止敌对进路经它侵入交叉点。"
- **带动 `{}`**："{道岔} 带动到{位置}——它与本进路上的 {同区段道岔} 同处 {道岔区段} 区段内。本进路不经过它，但 {区段} 随进路锁闭时会把它也锁住。若它留在 {不利位置}，锁死后将阻断 {平行进路方向} 的平行进路。故预先带动到 {正确位置} 以保证平行作业。"
- **邻接定位**："{道岔} 定位——它虽不在走行线上，但其所在区段与本进路 {区段} 同股道紧邻，定位时的直向连通关系到本进路区段电路的完整，故须锁定位。"

### 4.3 诊断学生错误

- **漏锁某道岔**："你漏了 {道岔}。它在本进路走行路径上（{股道}{位置}，{直向/侧向}），必须随进路锁闭；不锁则该道岔可被扳动，列车失去防护或误入他股道。"
- **该反位却选了定位**："{道岔} 应反位而非定位。本进路需在此从 {A} 切到 {B}；若定位，列车直向留在 {A}，到不了终点 {终端}，进路走不通。"
- **该定位却选了反位**："{道岔} 应定位而非反位。本进路在 {股道} 直向通过；反位会把列车引向 {他股道}，偏离本进路。"
- **漏防护**："{道岔} 应作定位防护 `[]`。它与本进路反位使用的 {另一组} 是交叉渡线，不锁定位防护，敌对进路可经交叉点侵入。"
- **带动写成使用/反之**："{道岔} 是带动 `{}` 而非联锁使用——它与 {同区段道岔} 同在 {区段} 内，进路不经过它，但因区段锁闭会把它一起锁住。不预先带动到 {正确位置}，它若留在 {不利位置} 被锁死，将阻断 {平行进路} 的建立。"
- **多锁无关道岔**："{道岔} 不该出现在道岔列。它既不在走行路径上，也不需为本进路防护或带动，锁它只会无谓限制平行作业。"

## 5. 敌对信号列：原理 + 解释 + 诊断

### 5.1 判定原理（通用）

先按 §3 复原"实际走行区段范围"。**敌对信号 = 下列各类的并集，再减去被锁死的**（逐架排查全站信号，排除本进路始端）：

1. **走行区段内的调车信号**：物理位于本进路**实际走行范围**内的调车信号，无论与本进路同向（追踪）或对向（迎面）。
   - 按实际经过范围取：换股道后，原股道切出点之外、新股道切入点之前的信号**不算**；新股道切入点起沿行进方向**前方**的信号**要算**。
2. **终到股道的终端信号**：
   - 接车至**有出站信号**的股道：**单一进路**列该出站信号本身；**变通进路**（分方式1/方式2 两行）**两行都**列其调车功能（出站信号名+D）。
   - 接车至**无出站信号**的股道：列该股道的调车终端信号。
3. **发车专有**：① 始端出站信号的**调车功能**（始端名+D）——每条发车进路必含；② 发车出口所经**方面的进站信号**（若出口经过它）。
4. **减去**：所有可行走行都被本进路锁闭道岔挡在占用区段之外、根本进不来的信号。

> 接车的进站信号（除本进路始端外）一般不列——它们在咽喉入口，多被本进路锁死。

### 5.2 解释模板

- **走行区段内调车信号（同向）**："{信号} 敌对——它是本进路走行区段 {区段} 内的调车信号，开放后其调车进路与本进路占用区段重叠，可能追尾/挤岔，故须封锁。"
- **对向（迎面）信号**："{信号} 敌对——它在本进路走行的 {股道} 上、朝向与本进路相反，开放会与本列车迎面冲突。"
- **终到股道终端信号**："{信号} 敌对——它是终到股道 {股道} 的终端信号，本进路占用该股道，须封锁其反向发车/调车。"（变通进路用其调车功能 `{信号}D`。）
- **发车始端调车功能**："{始端}D 敌对——本进路始端出站信号兼有调车功能，其调车进路与本发车进路直接冲突，须封锁。"
- **发车出口进站信号**："{进站信号} 敌对——本进路发车出口经过该方面进站信号处，对向接车会与本发车迎面冲突。"

### 5.3 诊断学生错误

- **漏封锁**："你漏了 {信号}。它是 {走行区段内的调车信号 / 终到股道终端信号 / 发车始端调车功能 / 出口进站信号}；不封锁则 {对应冲突} 可侵入本进路。"
- **多封锁**："{信号} 不该列敌对。原因（择一）：① 它不在本进路实际走行区段内（本进路只走 {股道}，未经它所在处）；② 它虽物理相邻，但本进路锁闭的 {道岔} 已把它挡在占用区段外，进不来。多列会不必要地限制平行作业。"
- **终端信号写错形式（S vs SD）**："终到股道终端信号：单一进路用出站信号本身，变通进路用其调车功能（+D）。本进路是 {单一/变通}，应写 {正确形式}。"
- **发车漏调车功能**："发车进路必封锁始端出站信号的调车功能 {始端}D，你漏了它。"

## 6. 轨道区段列：原理 + 解释 + 诊断

### 6.1 判定原理（通用）

- **无条件区段**：主路径**实际经过（占用）**的区段，沿行进方向列出。
  - 接车：从咽喉到站内，**含终到股道的站台 G 区段**。
  - 发车：从咽喉到站外，**不含出发股道的 G 区段**。
- **条件区段 `<S位置>R`**：道岔 **S 不在本进路道岔列**；当 S 处于某位置时，把【一个在本进路内的区段】与【一个不在本进路内的区段 R】电气连通（多因**无绝缘节侵限**）→ 需**条件检查 R 空闲**。
  - 精确判据（A 类）：对每个**不在道岔列**的道岔 S，取其定位/反位；若该位置下 S 连通的两段中**恰有一段在进路内、另一段 R 不在** → 列 `<S位置>R`。两段都在进路（或都不在）→ **不生成**。
- **硬约束（防过度生成）**：
  1. **在道岔列里的道岔（含带动 `{}`、防护 `[]`、使用的）一律不再生成条件区段**。带动就写在道岔列，不要挪成条件区段。
  2. 条件区段与无条件区段不重复。
  3. 拿不准时**宁可不列**——普通直股进路通常没有条件区段。

### 6.2 解释模板

- **无条件区段**："{区段} 占用——本进路列车实际经过该区段，须检查空闲并随进路锁闭。"
- **终到 G 段**："{G区段} 占用——接车列车终到停于该股道站台段，须占用检查。"
- **条件区段**："`<S位置>R`——道岔 S 不在本进路，但当它 {位置} 时，区段 R 与本进路占用的 {相邻区段} 电气连通（无绝缘节/侵限），故须条件检查 R 空闲，防止侧向车辆侵入。"

### 6.3 诊断学生错误

- **漏无条件区段**："你漏了 {区段}。本进路实际经过它，不检查空闲会有占用/追尾冲突。"
- **漏终到 G 段**："接车须占用检查终到股道站台段 {G区段}，你漏了它。"
- **漏条件区段**："你漏了条件区段 `<S位置>R`。道岔 S {位置} 时 R 与本进路侵限连通，须条件检查，否则侧向车可侵入。"
- **把带动/防护道岔写成条件区段**："`<(S)>R` 不对——S 已在本进路道岔列（带动/防护）。在道岔列的道岔不再生成条件区段。"
- **多列条件区段**："`<S位置>R` 不该有——该位置下 S 连通的两段并非'一段在进路、一段不在'（{说明}），不构成条件连通。"

## 7. 按钮列：原理 + 解释 + 诊断

### 7.1 判定原理（通用）

格式：`始端按钮，[变通按钮，] 终端按钮`
- **始端按钮** = 始端信号名 + 该信号 `button_suffix`（LA=列车按钮 / DA=调车按钮，从 JSON 读）。
- **接车终端按钮** = 终端信号名 + **该股道 `terminal_button_type`**（从 `tracks[].terminal_button_type` 读，**不是**信号自身的 button_suffix）。
- **发车终端按钮** = `external_directions[].departure_terminal_button`（从 JSON 读，不推导）。
- **变通按钮**：见 §9，**不参与考核**。

### 7.2 解释模板

- "始端按钮 {X} = 始端信号 {信号} 加它的按钮类型（列车按钮 LA / 调车按钮 DA）；办理进路先按它。"
- "终端按钮 {Y} = 终到 {股道} 股道的终端信号 {信号} 加**该股道规定的终端按钮类型**。按'始端、终端'两个按钮就定义了这条进路。"

### 7.3 诊断学生错误

- **终端按钮类型错**："终端按钮的后缀要按**该股道规定的终端按钮类型**来，不是照搬信号自己的类型。"（示例：某股道没有出站信号、终端只有调车信号，但按接车终端规定仍用列车按钮 LA，而不是调车按钮 DA。）
- **漏按钮**："排列进路要同时按下始端和终端两个按钮，你漏了 {缺的}。"
- **按钮取错信号**："始端 / 终端按钮应取 {正确信号}，你按的 {误取信号} 不是这条进路的始端 / 终端。"

## 8. 其余各列（简）

- **方面 / 进路内容**：`由{方面}方面{接车/发车}` + `{至/由}{股道}股道`。方面从 `external_directions[].entry_signals` 反查始端所属；股道从 receive/departure_tracks。
- **信号显示**：接车——全道岔定位→`U`（正线通过），任一反位→`UU`（侧线）；发车——从 `external_directions[].departure_signal_display` 读（方面级）。诊断漏/错时据此说明"因走侧线故 UU / 因走正线故 U"。
- **表示器**：发车从 `external_directions[].has_indicator` 读，true→`B`，false→空；接车空。
- **迎面进路(列车/调车)**：接车——目的股道 `has_train_departure_signal`=true 则迎面列车=该股道 G，迎面调车=该股道 G；无出站信号则迎面列车空、迎面调车=G。发车——两列空。
- **其他联锁**：发车=`BS`（闭塞条件），接车空。
- **进路号码**：递增序号，不参与联锁含义。

## 9. 进路方式与变通按钮（附注，**变通按钮不参与考核**）

### 9.1 何时分方式1/方式2

当列车进路的同一个始端和同一个终端间存在两条或两条以上平行进路时，联锁表除列出**基本进路**外，还应列出一条**主要变通进路**作为第二种进路方式。即使实际存在三条以上平行进路，联锁表通常也只收录其中两条。

联锁表中：**方式1 = 基本进路**，**方式2 = 变通进路（第一变通）**。

### 9.2 基本进路的选择原则（通用）

从多条平行进路中选定基本进路，按以下优先级依次比较：

| 优先级 | 判据 | 说明 |
|--------|------|------|
| **1（最高）** | 对平行作业影响最小 | 优先保证其他接车/发车/调车进路不受阻挡 |
| **2** | 走行距离较短 | 同等影响下选距离短的 |
| **3** | 经过道岔较少 | 同等条件下选道岔少的 |

**评估"对平行作业的影响"时，按以下顺序考虑**（书本原文）：
1. **首先**考虑不影响接车进路
2. **其次**考虑不影响发车进路
3. **最后**考虑少影响调车进路

> **解释时的表述**：给学生解释为何某条是基本进路时，不说"优先级1/2/3"，而说"这条进路不影响××方面的接车/发车作业，对平行作业干扰最小，故选为基本进路"。

### 9.3 示例（北京方面→III 股道接车）

北京方面向 III 股道接车可有三条平行进路：
- 经 5/7、1/3、9/11、13/15、17/19 道岔定位、**23/25 反位**
- 经 5/7 反位、9/11、13/15、21、**23/25 定位**
- 经 9/11 反位、5/7、1/3、13/15、21、23/25 定位

三条走行距离相近，故从**对平行作业影响**角度选：经 23/25 反位的进路不影响东郊方面至 5 股道的接车，对平行作业影响最小，故选为**基本进路（方式1）**；另选一条为变通进路（方式2）。联锁表只收录此两条。

### 9.4 变通按钮（**不参与考核**）

**变通按钮**（书本原文）：一种是**专设 BA**；另一种是**单置信号机的进路按钮**可兼作反方向调车进路的变更按钮（双置信号写作 `主A(副A)`）。
> **考核豁免**：变通按钮究竟落在方式1 还是方式2、以及用 BA 还是用某信号按钮，现有数据不足以唯一判定。故**变通按钮列不计入学生对错**，解释系统对该列不作评判。

## 10. 解释/诊断的统一流程

对学生办理的一条进路，逐列执行：

```
1. 据 §3 复原本进路走行事实（股道、换股道点、占用区段）。
2. FOR 每一列（道岔/敌对/区段/按钮…，跳过变通按钮）:
     正确集合 = 正确表该列元素
     学生集合 = 学生该列元素
     漏选 = 正确 − 学生   → 用对应列 §x.3 的"漏选"模板解释每一项为何必需
     多选 = 学生 − 正确   → 用"多选"模板解释每一项为何多余/有害
     位置/形式错（同一元素括号或后缀不同）→ 用"错选"模板解释正确位置与后果
3. 汇总：先陈述走行事实，再逐项给"缺什么/多什么/错在哪 + 为什么 + 不改的安全后果"。
```

**解释的三要素**（每条诊断都应具备）：**是什么错**（漏/多/错）、**为什么**（对应通用原理 + 本进路走行事实）、**安全后果**（不纠正会怎样：挤岔/追尾/迎面/侧撞/进路走不通）。

## 12. 车站数据文件规范（`station_topology.json`）

一切语义从这里读，规则正文不写死设备名。必备字段：

```json
{
  "external_directions": {
    "left|right": { "方面名": {
      "entry_signals": ["进站信号"],
      "receive_tracks": ["经渡线实际可终到的全部股道"],
      "departure_tracks": ["经渡线实际可始发的全部股道"],
      "departure_terminal_button": "发车终端按钮",
      "departure_throat_track": "该方面出站咽喉股道（发车路径追踪终点）",
      "has_indicator": true/false,
      "departure_signal_display": "L 或 L或U或LU（方面级发车显示串）"
    }}
  },
  "tracks": [{ "id", "exists_x_range", "terminal_signal",
               "terminal_button_type": "LA/DA（接车终端按钮后缀）",
               "has_train_departure_signal": true/false }],
  "signals": [{ "name", "track", "x", "direction(1下行/2上行)",
                "type(进站/出站/调车)", "button_suffix(LA/DA)" }],
  "switches": [{ "id", "connects", "type", 各道岔 x 坐标,
                 "no_insulation_on_side"?, "side_track"?, "side_covered_by_section"? }],
  "cross_double_crossovers": [["组A","组B"]],
  "sections": [{ "name", "track", "x_start", "x_end", "type", "contains",
                 "also_covers_track"? }],
  "switch_section_mapping": { "道岔": "区段" },
  "connectivity_graph": {
    "各股道 downstream 区段序列",
    "crossovers": [{ "id", "from_track", "from_section", "to_track", "to_section", "direction" }]
  }
}
```

| 字段 | 用途（解释/诊断时用到的关键点） |
|------|------|
| `signals[].direction` | 判定信号朝向 → 同向追踪还是对向迎面 |
| `signals[].type` | 进站/出站/调车 → 敌对分类、终端信号形式 |
| `signals[].button_suffix` | 始端按钮后缀 |
| `tracks[].terminal_button_type` | **接车终端按钮后缀（非信号自身 suffix）** |
| `tracks[].has_train_departure_signal` | 终端是否有出站信号 → 终端信号形式、迎面列车 |
| `external_directions[].receive/departure_tracks` | **穷举经渡线可达的全部终到/始发股道**（非进站信号所在股道），否则进路枚举缺失 |
| `external_directions[].departure_throat_track` | 发车走行追踪终点（发车须追到出站咽喉股道） |
| `external_directions[].departure_signal_display` | 发车信号显示串（方面级） |
| `cross_double_crossovers` | 交叉渡线配对 → 防护定位判定 |
| `insulation_exceptions` / `no_insulation_on_side` | 无绝缘节侵限 → 条件区段来源 |
| `connectivity_graph.crossovers[].direction` | 渡线方向性 → 判定某方向可用渡线（变通枚举、走行追踪） |

## 附：从生成到解释的要点（历史经验，防再犯）

- **敌对**：先追准走行区段，只取"实际走行范围"内的调车信号；发车必含始端调车功能与出口进站信号；减去被锁死的。
- **区段**：接车必含终到 G 段；带动/防护道岔不生成条件区段；条件区段只用 A 类精确连通判据，不逐边界扫描。
- **通用性**：以上均为原理；具体道岔/信号/区段/方面名一律来自数据。换车站时只换数据，规则不变。
