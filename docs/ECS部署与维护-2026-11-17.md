本地复用配置位于 `deploy/ecs`。执行 `npm --prefix framework/frontend run build` 后，运行 `python deploy/ecs/build_bundle.py`，可在 `.runtime/ecs-deploy` 生成发布包和文件哈希清单。发布包采用文件白名单，不包含本机运行目录、环境密钥或数据库。服务器镜像通过 `.dockerignore` 排除运行数据和凭据。

`prepare.sh` 用于首次部署，已有容器时不能直接重复执行；更新时先备份数据，再构建新的镜像并重建容器，保持同一个持久化目录。不要清空 `.runtime`，也不要删除初始化标记后尝试重新初始化。

## 日常维护

在 Workbench 的 Linux Shell 中执行：

```sh
docker ps --filter name=srtp
docker logs --tail 100 srtp
curl -fsS http://127.0.0.1:18000/api/health
docker restart srtp
nginx -t
```

容器重启会保留账号、作答和资料库文件。重启不是重新安装，不要重新运行空库初始化脚本。

更新前应备份整个 `.runtime`。需要一致性副本时，先停止 `srtp` 容器，归档 `.runtime` 后再启动；备份包含密钥和账号数据，应保存在服务器项目目录内并限制访问。没有配置自动备份任务。

AI 密钥可在管理员 AI 设置中保存并立即生效。容器通过 `SRTP_ENV_FILE=/app/.runtime/server.env` 选择持久化配置文件；启动时优先读取其中已保存的三个 `DEEPSEEK_*` 参数，避免 Docker 创建时捕获的旧环境变量覆盖新配置。维护者手动修改这三个 AI 参数后，重启容器即可加载；其他 Docker 环境变量的变更仍需重建容器。

### AI 保存权限修复

首次部署遗漏了 AI 配置写入路径的适配，原接口尝试写入容器代码目录 `/app/framework/backend/.env`，非 root 进程因此得到 `PermissionError`。现已改用已有的可写持久化文件 `server.env`，保留非 root 运行方式。保存使用原子替换及带引号的 dotenv 值；写入失败返回明确提示，不提前修改内存配置；未提交新 Key 时保留原 Key。

相关测试 6 项通过。线上已验证带管理员认证的保存接口、掩码回读、DeepSeek 实际连接测试，以及容器重启后的 Key 和模型持久化。使用模型 `deepseek-flash`，接口地址 `https://api.deepseek.com`。重启后仍为 182 道客观题及 18 道专题题。

更新前数据库备份保存在 `/opt/srtp/.runtime/backups/ai-config-20261117/railway.db`，作为此次更新的恢复资料保留。基础镜像 `srtp:20261117` 是修复镜像的构建依赖，继续保留。线上验证脚本位于 `deploy/ecs/verify_ai.py`，仅通过环境变量接收测试凭据，输出不包含密码、Key 或登录令牌。
