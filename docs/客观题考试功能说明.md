# 客观题考试

教师可以在现有“考试管理”中新建客观题考试。操作题考试继续保留；本次提供单独的客观题试卷，不混编操作题与客观题。

## 使用方式

1. 教师进入“考试管理 → 新建考试”，将考试类型设为“客观题考试”。
2. 填写名称、目标班级、开放与截止时间、答题时长。时间均按北京时间显示和填写。
3. 在题库中按章节、题型或题干搜索，添加题目，设置每题分值，并用上下按钮调整顺序。试卷最多100题，发布时总分必须为100分；未完成配置可以保存草稿。
4. 发布后，目标班级的现有启用学生可以在“考试界面”参加。名单、身份、题目、选项、答案、解析和判分规则在发布时冻结，后续改班、改题或删除源题不影响已发布考试。
5. 学生允许全屏后开始考试。答题卡显示完成进度，修改答案后自动保存，也可手动保存。交卷前会再次保存，并提示未答完整的题目。网络中断暂停输入，考试继续计时。
6. 教师在“考试批阅”查看逐题结果和自动判分成绩。页面预填卷面得分，教师可以核对、调整成绩并填写评语，保存草稿或直接发布。
7. 学生在历史考试中查看教师已发布的成绩；本场考试截止且本人成绩已发布后，显示本人逐题结果、标准答案和已有解析。多选显示漏选与误选，填空显示逐空比对结果。

每位学生每场考试只有一次正式机会，刷新或重新进入会恢复原答卷。个人截止时间取“开始时间加答题时长”和“本场截止时间”的较早者。沿用现有全屏规则：第一次退出须在60秒内恢复，第二次退出立即交卷。到时由服务器按已保存答案结算，断线和关闭浏览器不会延长考试。

## 题目范围与评分

组卷只使用现有182道已接入自动判分的客观题，以及教师明确新增、填写完整标准答案且通过现有校验的题目。其余184道原始客观题继续保留在项目资料中，不进入组卷范围。删除或失去有效判分规则的题目不能新加入试卷；草稿中的此类题目需移除后重新选题。

单选、判断必须与标准答案一致；多选必须完全匹配，漏选、误选均不得分；填空沿用题库已有的文字规范化、可接受写法和有序或无序匹配规则。每题全部答对获得本题分值，错答、未答或部分填写得0分。逐空诊断用于解释错误，不另给部分分。不调用AI生成评分规则或猜测答案。

## 数据与权限

- `objective_exam_papers` 保存草稿选题与分值，发布快照保存在既有 `exams.question_snapshot`。
- `objective_exam_responses` 保存学生答案、保存版本和交卷时的逐题评价。客观题考试复用既有考试答卷、全屏事件和成绩发布表，不创建仿真操作会话。
- 保存答案使用版本校验；相同内容的重试不会重复保存。旧版本的不同答案会被拒绝，前端保留本地输入并提示重新核对。
- 学生只能访问本人答卷。教师只能管理自己考试的名单、答卷和成绩，沿用既有权限边界。学生作答接口与下载接口在结果开放前不返回标准答案、私有规则或解析。
- 发布配置不能直接修改；无人开始时可以撤回，有人开始后只能复制为新考试。
- 原有操作题考试和人工成绩发布流程保留。

首次启动新后端时会自动升级旧数据库：先在项目内 `.runtime/exam-backups` 创建并校验完整备份，再解除考试答卷ID对操作会话的专用外键，保留其余约束及原答卷和关联成绩。升级在事务中比对原答卷内容、原表记录数及外键关联，异常时回滚。空数据库直接创建新结构。正式数据库备份应保留，不能上传公开仓库。

## 验证方式

新增后端测试 `framework/backend/tests/test_objective_exams.py` 覆盖题库范围、四类题型、发布冻结、名单、权限、保存冲突与重试、未答与部分填写、限时和全屏结算、并发、成绩开放，以及旧操作答卷和成绩的升级保留。

新增前端测试 `framework/frontend/tests/objective-exams.test.mjs` 与扩展的 `exam-page.test.mjs` 覆盖组卷参数、答题进度、连续保存、响应丢失、本机恢复、冲突保护和交卷等待保存。

2026-11-17 使用隔离数据库和临时账号完成浏览器验收：教师从182道题库选题、改分、排序和发布，学生全屏答题、保存、重新读取和交卷，教师核对并发布成绩，学生查分，以及截止后的逐题结果。检查了桌面与390像素窄屏显示。验收数据未写入现有教学数据库。

验证结果：后端相关回归联测145项通过；旧库升级测试修正连接池外键设置与测试备份关闭方式后单独复测通过，合计覆盖146项。前端考试相关43项测试通过，包含断线或全屏暂停恢复后的自动保存，生产构建通过。后端联测范围包括客观题考试、原操作题考试、人工成绩、批阅队列、操作评价、教师客观题管理和章节练习。
