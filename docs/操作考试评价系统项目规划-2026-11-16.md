# 操作考试评价系统详细项目规划

日期：2026-11-16。状态：评审稿，尚未实施。

后续已获得用户实施授权。本文保留最初规划，首期实际交付、验收入口和验证结果以[实施记录](操作考试评价实施记录-2026-11-16.md)为准；未完成的教学校准或长期运行验证不按规划勾选代替。

本次交付是评分标准、日志分析与项目规划，不包含评分功能开发、数据库迁移、日志删除或GitHub上传。

配套文件：[评分标准V1.0](操作考试评分标准-V1.0-2026-11-16.md)、[日志容量与治理](操作考试日志容量与治理-2026-11-16.md)。

## 1. 目标与交付边界

将操作考试从“教师逐条对照点击日志录分”，逐步改为“服务端记录事实、后端按冻结规则生成可追溯建议分、教师确认发布、AI可选生成学生评语”。

首期支持标准站“正常办理一条指定接车进路”，支持误选后清除、错误进路取消与恢复、多次尝试、业务拒绝、核心目标未完成、截止边界及证据不足。标准示范用于教学与验证，不再把整段点击完全一致作为正式考试的评分条件。

AI仅生成面向学生的评语草稿。评分、错误归类、关键违规、规则生成、教师评分建议和考试实时指导均由确定性程序与教师流程承担，不调用AI完成。

保持现有正式考试、教师操作录题、教师管理本人考试、人工成绩及发布审计、学生本人历史、账号权限和全屏封卷流程。管理员仍仅有平台管理与账号导航，不因为后台管理权限新增教学入口。自由仿真不写入考试或实验学习记录。

首期不扩展引导接车、故障处置、列车接车全过程、多人协同、多题编排、全站行为等价验证，也不更改客观题库、实验专题及章节AI助教。本次“AI仅生成学生评语”的限制针对新增操作考试评价能力，不据此擅自删除其他已授权AI功能。

## 2. 当前系统事实与缺口

| 模块 | 已确认事实 | 本次需要补齐 |
| --- | --- | --- |
| 教师录题 | 题目版本、初始条件、标准录制、发布检查已存在 | 结构化目标、允许路径、评分模板和专业确认 |
| 操作事件 | `OperationEvent`逐条保存业务点击，包含事件ID、顺序和接受结果 | 稳定原因编号、业务关联、状态差量 |
| 运行状态 | 当前状态可持久化恢复，累计运行事件在JSON中保存 | 完整业务事件独立追加、历史与状态分离 |
| 操作学习 | 当前严格比较归一化点击序列，一致为100、差异为错误且不自动给分 | 首期保持兼容，不同时改造成新评分入口 |
| 考试封卷 | 服务端时间、幂等封卷、全屏控制已存在 | 截止时状态证据与自动事件时间边界 |
| 教师批阅 | 人工草稿、确认、发布版本和审计已存在 | 自动评价展示、人工调整理由、评语草稿关联 |
| AI配置 | 管理员配置的模型、地址、密钥供后端使用 | 新增评语服务复用配置，不新增配置入口 |
| 日志访问 | 控制台每秒刷新，响应中取回全部点击 | 增量同步、后端分页、无变化轻量响应 |

特别注意：现有`seal()`主要设置会话与答卷的封存状态，没有专门按考试截止时间生成评分所需的最终站场证据；`detail()`也不会自动为已封卷答卷推进和核验所有延时事件。这是待解决的实现缺口，不是已经验证发生过错误评分。

当前引擎在刷新等操作中推进部分延时状态，记录时间可能更接近观察时间。不能通过“封卷后用现在的时间刷新一次”补出截止前的成绩事实，迟到结算尤其需要按截止时点处理。

## 3. 总体处理流程

```text
教师录制示范
  → 选择首期评分模板并确认结构化目标、允许路径及关键规则
  → 校验标准轨迹能完成目标、初始条件可解
  → 发布时冻结题设、评分规则、站场及运行版本
  → 学生操作：服务端原子保存点击、业务事件、当前状态
  → 截止/主动交卷：确定截止时点并封存可靠证据
  → 后端异步或封卷后独立任务计算建议分
  → 教师核对证据、接受或调整成绩与事实摘要
  → 可选生成AI学生评语，教师检查或编辑
  → 沿用成绩发布，学生查看本人已发布内容
```

第一版不强制引入Redis、Celery、SSE、WebSocket或流程挖掘依赖。评分是本地确定性任务，先用数据库持久任务状态和受控后台工作循环；AI调用和归档压缩都在数据库写事务外执行。若实际部署能力不适合后台循环，可采用独立管理进程，任务与结果约束不变。

## 4. 目标模型与规则配置

### 4.1 题目评价配置

建议在操作题版本中增加结构化配置快照，具体数据库字段名在实施时统一：

| 字段 | 用途 |
| --- | --- |
| `assessment_schema_version` | 配置结构版本 |
| `task_type` | 首期固定为正常接车进路办理 |
| `goal_route_ids` | 认可的目标进路标识集合；通常一条 |
| `required_mode` | 办理方式，不能只检查终点 |
| `required_signals` | 题目要求的信号及认可显示 |
| `end_condition` | 交卷时必须保持的进路、信号及遗留状态条件 |
| `allowed_variants` | 经教师确认的合法路径/操作约束，不限定全部点击一一相同 |
| `impact_scope` | 需要核验的本站设备与资源范围 |
| `rubric_id/version` | 使用的评分模板及版本 |
| `critical_rules` | 审核过的关键规则及上限 |
| `review_metadata` | 专业确认人与时间 |

首期配置界面使用模板和选择控件，不开放任意Python代码、任意表达式或自由文本规则执行。教师可以说明任务，但程序只依据结构化、已审核配置计算。

### 4.2 版本冻结

考试发布时保存完整评价配置、模板快照及其哈希，继续保存题干、初始状态和标准示范。`station_version`目前是站场包哈希，不能独自代表运行算法版本；须额外标识可追溯的引擎版本和评分程序版本。

引擎代码发布版本应能映射到实际代码构建；当前未提交工作区不能仅使用Git提交号冒充精确运行版本。必要时使用构建清单及相关源文件哈希。

不允许题目发布后直接覆盖同一考试的规则。克隆考试可使用新配置，既有学生答卷继续绑定旧快照。多版本并存不意味着必须在首期运行多个旧引擎；不支持的旧版本进入只读人工批阅。

## 5. 事件证据与时间设计

### 5.1 一次点击的事务边界

服务端校验会话、权限、考试时间、全屏状态和事件幂等→执行业务操作→收集此次业务事件和差量→在同一事务写入点击、业务事件、状态与修订号→提交后返回确认。

同一事件ID重复请求应返回原确认，不再执行、不再新增扣分。并发冲突时事件和状态一并回滚，不能出现日志记录成功但站场没变化，或站场变化但证据没落盘。

### 5.2 业务事件

拟新增`OperationBusinessEvent`，使用会话内连续序号及唯一约束。至少记录：

- 会话、事件ID、业务序号、来源点击ID或系统来源。
- 事件类型、原因编号、设备标识和办理实例标识。
- 服务端记录时间、业务逻辑生效时间、必要的计划到期时间。
- 最小前后状态差量、影响资源集合及状态修订引用。
- 引擎/事件结构版本和可用于完整性校验的哈希。

已有运行事件可作为迁移来源，但须确认哪些包含可靠时间、原因、设备和办理实例，不能把提示文字自动解析成完整新证据。

### 5.3 封卷时点

主动交卷按服务端受理的交卷时点；截止、全屏超时等按现有规则确定的实际生效截止时点。统一输出`cutoff_at`，不得以后台扫到该答卷的时刻替代。

需要为引擎引入可注入的时钟/时间推进入口，覆盖相关模块的定时器，而不是只替换一个函数中的`now()`。对截止前可确定完成的自动事件，按冻结条件推进至截止；截止后的点击和自动结果不得授予截止前分数。

特别处理分阶段延时：道岔结束、光带建立、信号开放、取消光带更新和取消完成存在依赖。必须按逻辑时间顺序推进，不能把延迟观察时间当作所有后续阶段的起点，也不能在条件不全时凭计划时间补成功。

遇到无法可靠复原截止状态、重启期间输入不可确定或跨版本不兼容，封存已有事实并标为待复核。评分任务不自行补写或修改原始考试事件。

### 5.4 证据封存

拟新增`ExamEvidenceSeal`：保存截止时点、初末状态引用、点击和业务最大序号、完整性摘要、版本及证据状态。封存与答卷状态更新在同一事务完成；较重的评分计算在之后执行。

如封存计算失败，不能让考试继续接受超时操作；先持久化已结束状态和证据异常，再由恢复任务补封存或转人工。幂等重试不得改变截止时间、制造第二份可变原始证据。

## 6. 后端评价模块

建议新增目录`app/services/operation_assessment/`，避免把新评分堆入考试时间与权限服务。

| 模块 | 职责 |
| --- | --- |
| `evidence.py` | 读取封存证据，校验版本、连续性与状态关联 |
| `goals.py` | 判断A1—A4及截止完成情况 |
| `episodes.py` | 构建错误片段，关联实际资源影响和恢复结果 |
| `rules.py` | 执行已冻结的B/C及关键规则 |
| `scorer.py` | 去重、分项计算、应用上限并生成评价明细 |
| `service.py` | 任务领取、幂等保存、查询与人工复核状态 |
| `commentary.py` | 仅生成学生评语，读取确认后的白名单摘要 |

评分核心应是可重复调用的纯计算接口：输入冻结配置及证据，输出结构化评价；不在计算中读当前题库新规则、不请求AI、不修改运行状态。

拟新增`ExamEvaluation`，保存评价版本、状态、A/B/C、原始分、适用上限、建议分、目标结果、错误片段、证据引用、配置/证据/引擎/评分哈希。缺失关键证据时`suggested_score=null`。

相同证据、评分版本和配置应命中同一结果，重复任务不插入无意义版本。教师显式复核重算可建立新版本，并记录触发原因；已发布成绩不随重算自动覆盖。

## 7. 教师和学生界面

### 7.1 教师录题/考试配置

在既有录题流程增加“评价设置”：选择模板→选择目标进路和结束条件→核对允许操作→确认关键规则→预演示范评分。显示标准示范是否能取得100分；有意包含错误的录制不得直接作为满分示范发布。

对旧题目提供“未配置自动评价，继续人工批阅”，不强迫修改全部历史题目。新配置发布后冻结，编辑产生新版本。

### 7.2 教师批阅页

在既有答卷中增加：

- 评价状态、建议分、A/B/C明细和关键上限。
- 已完成目标、未完成条件和截止状态。
- 错误片段、恢复情况、扣分及可点击的证据定位。
- “采用建议分”“人工调整”及调整理由；教师确认可发布事实摘要。
- 可选“生成学生评语”，失败可重试或手写。
- 评价版本、教师修改和历史发布版本。

系统明确区分后端建议分、教师最终成绩、未发布AI草稿和学生已发布内容。未取得建议分时不填0，不将服务异常误显示为学生0分。

### 7.3 学生界面

考试中保留站场、题目、计时和既有业务提示；不新增实时得分、错误定位或AI辅助。交卷后保持“待教师发布”，不提前泄露自动建议分。

成绩发布后，学生查看本人最终成绩、教师批准的简明分项/扣分原因和学生评语；不暴露内部规则代码、标准操作全日志和其他账号记录。成绩更正沿用原发布版本机制。

### 7.4 API草案

以下为拟议语义，实施时核对现有路由，路径不代表已经提供：

| 接口语义 | 访问与约束 |
| --- | --- |
| 读取/保存题目评价配置 | 教师按既有录题权限，草稿可改、发布冻结 |
| 查询答卷评价 | 管理本人考试的教师；学生仅能查询发布后的本人可见投影 |
| 请求重新评价 | 教师显式操作，限已封卷答卷，保留版本，不更改已发布成绩 |
| 按游标读取点击/业务事件 | 按答卷权限，服务端分页并限制条数 |
| 接受建议分或保存人工调整 | 使用现有成绩修订号进行并发校验，记录采用的评价版本 |
| 生成学生评语草稿 | 教师确认事实和成绩后触发；绑定摘要与修订号 |
| 发布 | 沿用现有成绩发布；需校验评语未过期 |

评分、日志和AI的入口都复用考试所有权校验，不能只判断调用人是教师就放行。

## 8. AI学生评语实施要求

复用管理员配置，后台只发送必要白名单，不新增AI权限或教学入口。调用基于教师确认的事实与最终分数，输出仅为评语文本。

增加评语任务状态、摘要哈希、成绩修订号、生成令牌和超时租约；调用在写事务外进行，响应回写须同时匹配令牌与当前摘要/成绩修订。教师期间改分、改事实或改评语，旧响应不得覆盖。

AI没有“建议分”“异常分类”“规则草稿”等字段。后端对返回长度、格式、分数表达及明显越界内容进行基础校验，但不能声称程序能自动验证全部自然语言事实；教师预览是正式发布前的质量检查。失败保留手工评语，分数不变。

通过替身测试验证不同AI输出均不能改写评价和成绩。真实调用在后期使用不含身份的合成评价摘要验证连接与格式，不上传真实答卷全量日志；调用可用性不能当作评语专业正确性的证明。

## 9. 日志治理工作包

具体容量和归档条件见配套文档。实施分两步：

1. 首期必做：独立追加业务事件、避免完整历史随状态重写、增量日志接口、无变化轻量轮询、静态站场与题目按版本缓存、日志后端分页、AI摘要输入。
2. 正式扩大使用前完成：单卷容量指标、归档导出与恢复、保留条件及申诉冻结、备份轮转和磁盘预警。

不在首期删除历史点击、抽样丢弃关键操作、保存逐秒截图或录屏。必要的初末状态与有限检查点用于追溯；归档前恢复验证通过才有资格移除在线重复证据。

## 10. 数据迁移与兼容

采用新增表、可空字段和旧格式兼容读取，先保持现有人工成绩服务可用。

迁移前在项目目录内建立一致性数据库备份，并核对恢复副本。记录各表行数、关键关联数及既有发布成绩摘要；迁移后核对，验证账号、客观题、实验专题、操作学习、考试、教师成绩和发布版本保留。

历史答卷不自动生成新制成绩。可选人工触发证据检查；具备完整证据并明确说明使用新标准复核时才建立新评价版本。缺少截止状态或运行版本的一律保持人工批阅，不逆向猜测。

新增历史迁移不得利用`data.xls`或其他教学答案覆盖标准站数据，不重新导入已删除题目，不改动当前182道自动判分客观题范围。

升级可重复执行，数据库变更有版本记录。事件历史搬迁采用可核验的短事务批次，避免长时间占用SQLite写锁；考试进行中不做破坏性搬迁和数据库整理。

## 11. 阶段、工作量与验收门槛

以下为一名熟悉仓库的开发者的工作量估算，不是日历承诺；教师审核、业务分歧、环境问题和需求变化可能增加时间。建议总体15—22人日，按阶段交付，教师校准另需安排实际参与时间。

| 阶段 | 预计人日 | 主要任务 | 可审查产物与准入条件 |
| --- | ---: | --- | --- |
| P0 评分与场景定稿 | 1—2 | 教师确认A/B/C、关键规则、目标、样例轨迹；核对可观测证据 | 冻结首期标准、合法路径及验收案例；无法证明的规则不启用 |
| P1 事件与截止证据 | 4—5 | 时钟入口、业务事件、事务关联、封存、重试与重启边界 | 可可靠区分误选/锁闭/开放/恢复；迟到结算不越过截止授分 |
| P2 确定性评分 | 3—4 | 目标检查、错误片段、扣分去重、上限、评价版本 | 算例结果可重复，缺证据转人工，评分不调用AI |
| P3 教师及学生集成 | 3—4 | 题目配置、批阅明细、人工调整、发布投影、学生历史 | 现有人工流程保留，权限和成绩版本不回退 |
| P4 AI评语与日志优化 | 2—3 | 评语白名单/租约/过期保护、增量传输、状态与历史分离 | AI只产生评语，无变化轮询不返回完整历史 |
| P5 校准、压测与交付 | 2—4 | 教师对照评分、并发/容量、迁移恢复与归档演练、浏览器验收 | 关键分歧解决，容量与性能有记录，人工回退已演练 |

这些阶段有依赖关系，不能跳过P1就接AI评语后宣称完成评价系统。日志历史与状态分离涉及P1的数据结构，应在P1确定、P4完成访问优化；不是P4才开始考虑证据保存。

教师校准建议：至少两名教师先独立评价20—30组覆盖主要分界的合成轨迹，再查看系统建议。所有关键违规、及格边界和明显不同扣分的分歧逐项说明处理；其余分差统计作为调参依据，不能只报告平均接近就上线。

## 13. 启用策略与回退

建议配置开关：证据增强、自动评价、AI学生评语分别控制。关闭AI不影响评分；关闭自动评价仍可人工批阅；已发布成绩始终可见。

启用顺序：

1. 合成数据验证，确认完整评分矩阵和迁移恢复。
2. 小范围影子评价：教师照常评分，自动结果仅供事后对照，不影响学生成绩。
3. 通过校准的单一模板启用教师可见建议分，继续人工确认发布。
4. 经过容量、权限和异常演练后扩大班级范围。

发生错分时先关闭自动建议展示，保留原始证据与所有评价版本，由教师按原流程处理；不得删除证据或覆盖已发布成绩来掩盖问题。部署回退保留新增兼容表，避免用旧备份覆盖部署后的有效学生提交。确需恢复整库时另做维护及数据合并方案。

## 14. 主要风险及应对

| 风险 | 应对 |
| --- | --- |
| 只按按钮序列，误罚合法纠错和替代路径 | 目标状态＋业务事件＋片段分类，标准日志仅作示范 |
| 截止后才观察到信号开放，错误授分 | 可注入时钟、逻辑时间和截止证据；不能证明则复核 |
| 提示文字变化导致误判 | 原因编号和状态差量，不使用文本相似度判分 |
| 特殊操作一概当违规 | 按题型和冻结允许列表，教师审核关键规则 |
| 不完整日志仍输出精确分 | 完整性检查失败时不生成自动总分 |
| SQLite写锁和全局锁拖慢同步 | 无变化少写、历史独立追加、短事务、压力测量；之后再决策架构调整 |
| AI评语编造专业事实或覆盖新成绩 | 白名单摘要、仅评语、教师预览、版本和令牌保护 |
| 归档后无法申诉 | 保留版本和完整证据，恢复验证及申诉冻结 |
| 改造破坏已有课程与人工成绩 | 功能开关、增量迁移、隔离测试和完整回归 |
